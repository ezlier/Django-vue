# 大数据概述

## 大数据特征：

- 数据量大（volume）
- 数据类型繁多（variety）
- 处理速度快（velocity)
- 价值密度低（value）
- 真实性（veracity)

## 大数据对科学研究的影响：

催生第四种科研范式：数据密集型科学范式

## 对思维的影响：

- 全样而非抽样
- 效率而非精确
- 相关而非因果

- 批处理计算(静态大数据，MapReduce)
- 流计算(流数据，Storm/Flink)
- 图计算(复杂网络关系，GraphX/Pregel)

# HDFS

## 体系结构

HDFS采用了主从（Master/Slave）结构模型，一个HDFS集群包括一个名称节点(NameNode）和若干个数据节点(DataNode）。

## 局限性

- 不适合低延迟数据访问
- 无法高效存储大量小文件
- 不支持并发写入和任意修改

## 名称节点数据结构

1. **FsImage**磁盘镜像，保存 HDFS 文件系统**完整元数据快照**，持久化在磁盘。
2. **EditLog**编辑日志，记录文件增删改操作，**实时写入磁盘**。


## 名称节点的功能

是整个HDFS的大脑，管理文件系统的命名空间，管理数据块，与DataNode的映射关系，处理客户端的读写请求

## 第二名称节点

定期合并FsImage和EditLog，防止EditLog文件过大导致NameNode重启慢，合并后的镜像推回给NameNode

## 两个核心配置文件

core-site.xml（核心配置）与hdfs-site.xml (HDFS配置)

## HDFS命令


```plaintext
hdfs dfs 后接Linux文件命令
```


# MapReduce

## 核心思想



MapReduce设计的一个理念就是“**计算向数据靠拢**“和“**分而治之**”

## Shuffle过程

- 输入与环形缓冲区：先写入内存中的环形缓冲区(defult:100MB)
- 溢写(Spill)：当缓冲区达到阈值，系统会锁定缓冲区中的数据，准备写入本地磁盘
- 排序(Sort)：在写磁盘之前，必须在内存中对数据进行排序（按照key进行）
- 合并(Combiner)：如果配置了Combiner，会在排序后进行一次局部聚合，减少写入磁盘的数据量
- 归并(Merge)：随着Map的不断输出，磁盘上会生成多个溢写的小文件。Map任务结束前，会将这些小文件归并成一个大的，有序的输出文件

## MapReduce执行过程

**输入分片（Input Split）**：HDFS 将输入文件切分为多个分片（Split），每个分片由一个 Map 任务处理（分片大小通常与 HDFS 块大小一致，默认 128MB）。

- 示例输入（文本文件）：`hello world \n hello mapreduce`

**Map 阶段**：

- 输入：<行号，行内容>，如`<0, hello world>`、`<1, hello mapreduce>`
- 处理：按空格拆分单词，输出 <单词，1> 的键值对
- 输出：`<hello,1>`、`<world,1>`、`<hello,1>`、`<mapreduce,1>`

**Shuffle 阶段**：如上述 Shuffle 过程，最终 Reduce 端拿到分组后的数据：`<hello, [1,1]>`、`<world, [1]>`、`<mapreduce, [1]>`

**Reduce 阶段**：

- 输入：<单词，迭代器（Value 列表）>，如`<hello, [1,1]>`
- 处理：对 Value 列表求和，统计单词总次数
- 输出：`<hello,2>`、`<world,1>`、`<mapreduce,1>`

**结果输出**：Reduce 输出结果写入 HDFS 指定目录，文件内容为：

```plaintext
hello	2
world	1
mapreduce	1
```


# Hive

## Hive的特点

- 针对海量数据的高性能查询和分析系统，Hive可以高效的对TB甚至PB级的数据进行处理。
- 类SQL的查询语言，一个熟悉SQL的用户基本不需要培训就可以非常容易的使用Hive进行很复杂的查询。
- HiveQL灵活的可扩展性，用户还可以自定义其使用的数据类型。
- 高扩展性和容错性，用户查询的执行是通过MapReduce框架实现的。
- 与Hadoop其他产品完全兼容，Hive支持各种数据源和数据格式。

## Hive系统架构

Hive是底层封装了Hadoop的数据仓库处理工具，它运行在Hadoop基础上，其系统架构组成主要包含4个部分，分别是用户接口、跨语言服务、底层的驱动引擎以及元数据存储系统。

## 数据类型

基本数据类型：INT,STRING,BOOLEAN,DOUBLE

复杂数据类型：ARRAY,MAP,STRUCT

# NoSQL与关系型数据库的比较

|    特性    |          关系型数据库（MySQL/Oracle）          |         NoSQL 数据库（MongoDB/HBase/Cassandra）         |
| :--------: | :--------------------------------------------: | :-----------------------------------------------------: |
|  数据模型  |      结构化数据，严格遵循表结构、字段类型      | 非结构化 / 半结构化，支持键值、文档、列族、图等灵活模型 |
|  事务特性  |  支持 ACID（原子性、一致性、隔离性、持久性）   |     多数不支持完整 ACID，部分支持最终一致性（BASE）     |
|   扩展性   |     垂直扩展（升级硬件）为主，水平扩展复杂     |          天生支持水平扩展，可轻松扩容集群节点           |
|  查询能力  |      支持复杂 SQL 查询、多表关联（JOIN）       |  简化查询语言，不支持复杂 JOIN（部分可通过应用层实现）  |
|    性能    | 对小规模结构化数据查询高效，海量数据下性能下降 |      高并发、海量数据读写性能优异，适合高吞吐场景       |
| 数据一致性 |                    强一致性                    |       弱一致性 / 最终一致性（部分可配置强一致性）       |
|  适用场景  |   金融、电商交易等对事务、一致性要求高的场景   |  大数据分析、社交网络、物联网等非结构化 / 海量数据场景  |
| 模式灵活性 |            静态模式，表结构变更复杂            |        动态模式，无需预定义结构，字段可灵活增减         |
